Detection model config: ai/train_model.py

Algorithmscikit-learn IsolationForest, 100 trees, contamination 0.2
Featuresrequests per minute, failed authentications (per UE and slice, last 60 s)
Training data11 hand-written synthetic rows
Output-1 = anomaly, request blocked with HTTP 403 and written to alerts.log
Observed triggerabout 144 or more requests per minute with no failed logins (measured on the committed model)

Decision order inside the AMF from the code

  1. Count this UE's requests and failures in the last 60 seconds.
  2. Ask the model. If anomalous: HTTP 403 blocked_by_ai, increment threat and blocked counters, append to alerts.log.
  3. Check the slice against the allowlist. If not allowed: HTTP 403 unauthorized slice, increment blocked.
  4. Authenticate at AUSF, create the session at SMF, register at NRF, reply 201.

Security controls from the repository

ControlHow it is implemented
Mutual TLSAll four functions use CERT_REQUIRED; private CA and per-function certificates from gen_certs.sh
Micro-segmentationNetworkPolicies in security/: default deny, AMF flows, NRF only from AMF
Tenant isolationNamespaces tenant-a, tenant-b, tenant-industrial, tenant-medical with edge-isolation.yaml
Slice protectionAllowlist plus AI anomaly check at the AMF
MonitoringPrometheus scrapes /metrics from each function every 5 s; Grafana alert
Compliance checksShell scripts in compliance/: deployment health, ETSI-style, security and zero-trust checks

CI/CD pipeline Jenkinsfile stages

  1. Checkout from GitHub
  2. Generate certificates
  3. Compliance checks
  4. Build base image, then AMF, NRF, AUSF, SMF images in parallel
  5. Security scan (Trivy), optional stage
  6. Deploy to Kubernetes (K3s)
  7. Verify rollout of all four deployments

This list is the pipeline definition. Build results live in Jenkins.
